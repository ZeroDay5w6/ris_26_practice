Практическая работа №4

Последовательность машинных операций для простых вычислений. ОП.03 Архитектура аппаратных средств

Главная идея

Процессор не умеет считать «в памяти». Он берёт числа в свои быстрые ячейки (регистры), считает там, и только потом кладёт результат обратно. Это как повар: продукты лежат на складе, а резать их можно только на рабочем столе.

Память = склад

Большая, но далеко. Адреса: A, B, C, Y.

Регистры = стол

Маленькие, но рядом и быстрые: R0, R1, R2.

6 команд

LOAD R, X — со склада на стол (память X → регистр R)

STORE R, X — со стола на склад (регистр R → память X)

ADD R1, R2 — R1 = R1 + R2

SUB R1, R2 — R1 = R1 − R2

MUL R1, R2 — R1 = R1 × R2

MOV R1, R2 — копия R2 в R1

Результат всегда остаётся в первом регистре. Старое значение там пропадает.

Рецепт для любой формулы

1. Загрузи нужные числа (LOAD). 2. Посчитай по приоритету: сначала умножение, потом сложение. 3. Сохрани результат (STORE).

Где это встречается в жизни

Каждый раз, когда вы платите картой, считаете чек или смотрите баланс игры, под капотом идёт та же цепочка: достать числа, посчитать, записать итог.

Чек в кафе: X = A + B − C

A — кофе (10), B — десерт (5), C — скидка по карте (3). Касса делает LOAD, LOAD, ADD, LOAD, SUB, STORE. Итог: 12.

Поездка на группу: Y = (A + B) × C

Билет (A) плюс обед (B), умножить на число человек (C). Скобки — это порядок: сначала ADD, потом MUL.

Магазин: Z = A·B + C·D

Цена × количество для двух товаров. Две «мини-задачи» в разных регистрах, потом сложение.

Игра и телефон

Урон = сила × множитель, потом из здоровья вычитается урон. Приложение банка: баланс − платёж. Всё это те же LOAD, MUL, SUB, STORE.

Как запомнить навсегда: склад → стол → считаем → склад. Если можешь сказать это вслух для любой формулы, ты понял тему.

Вычисли: «Сумма заказа = цена × кол-во». Какая команда стоит между двумя LOAD и STORE?

Задание 4. Ответы на вопросы

Сначала ответь сам, потом открой.

1. Почему нельзя A + B → Y прямо в памяти?

Арифметическое устройство работает только с регистрами. Память медленная и далеко, поэтому данные сначала переносят в регистры (LOAD), считают, затем возвращают (STORE).

2. Сколько регистров нужно для задания 3?

Достаточно трёх. R0=A, R1=B, MUL R0,R1. Затем R1=C, R2=D, MUL R1,R2, и ADD R0,R1. Можно обойтись и двумя, если сначала сохранить промежуточный результат в память, но это медленнее.

3. Что будет, если в ADD R0,R1 сначала загрузить C, а не A?

Получится C + B вместо A + B. Для A=10, B=5, C=3 это 8 вместо 15. Машина выполняет команды буквально и не знает, что вы хотели.

Контрольные вопросы

1. Почему важен приоритет операций?

Команды выполняются строго по порядку. 2 + 3 × 4 = 14, а не 20. Если сначала сложить, получим неверный результат.

2. Как сокращение числа регистров влияет на производительность?

Меньше регистров значит больше обращений к памяти (лишние LOAD/STORE). Память медленнее, поэтому программа работает дольше.

3. Может ли переменная быть в нескольких командах?

Да. Для A·A + A: LOAD R0,A; LOAD R1,A; MUL R0,R1; LOAD R1,A; ADD R0,R1; STORE R0,Z. Значение в памяти не меняется, пока не сделать STORE.
